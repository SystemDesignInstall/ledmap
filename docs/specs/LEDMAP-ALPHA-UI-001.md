# LEDMAP-ALPHA-UI-001 — Early Alpha UI: Cabinet Grid Visualizer

Статус: **Accepted — план реализации одобрен пользователем 2026-09-23**. Основание: Phase 4E принята пользователем на commit `67fd975cf0e0036fd50c06d533a13a1bff871651`. Изменение очередности этапов описано в [ADR-017](../DECISIONS.md#adr-017-early-alpha-ui--cabinet-grid-visualizer).

## 1. Цель и границы

Первая запускаемая через `npm run dev` версия: Electron window → Create Screen → Cabinet Grid settings → существующий Cabinet Engine → Canvas preview. Один Screen с одной прямоугольной сеткой одинаковых кабинетов; состояние живёт в памяти до закрытия приложения.

Alpha визуализирует готовый Cabinet Engine. Полный доменный pipeline сохраняется; Input Canvas и Mapping Region здесь не создаются, соответствие Input→Output не вычисляется. Hardware Engine, Receiver/Port/Processor, PixelAddress, dataIndex, globalRemapIndex, Mapping/Remap, Open/Save `.ledmap`, экспорт и packaging остаются отдельными этапами. StartCorner фиксирован в `top-left`; новые математические режимы не добавляются.

## 2. Пользовательский сценарий

1. Открывается окно с действием **Create Screen**. Оно создаёт `Screen 1` и его единственную сетку с параметрами ниже; после создания действие недоступно.
2. Слева расположены настройки, справа — Canvas, рядом — вычисленные размеры. Каждое допустимое изменение немедленно обновляет preview.
3. Canvas показывает физическую сетку, границы модулей и направленный путь обхода кабинетов. Масштаб автоматически вписывает сетку в доступную область с сохранением пропорций пиксельной геометрии, в том числе при resize окна.
4. В кабинете отдельно подписаны физический ID `C01…` и логический номер `#1…`. Легенда поясняет оба обозначения. ID назначаются по физическим строкам слева направо и не меняются при переключении ordering; логический номер равен `cabinetIndex + 1`. Координаты core остаются 0-based.

| Настройка | Начальное значение | Допустимые значения |
|---|---|---|
| Columns / Rows | 4 / 3 | Положительные безопасные целые, в пределах лимита preview |
| Module columns / rows | 4 / 4 | Положительные безопасные целые |
| Module pixel width / height | 32 / 32 | Положительные безопасные целые |
| Numbering | Row | Row / Column |
| Direction | Left → Right | Row: LTR / RTL; Column: TTB / BTT |
| Snake | ON | ON / OFF |
| StartCorner | Top Left | Фиксированное значение, без редактора |

При смене Numbering направление переводится по соответствию LTR ↔ TTB, RTL ↔ BTT; Snake сохраняется. Numbering, Direction и Snake остаются отдельными настройками. Module ordering и pixel ordering внутри Module фиксированы: Row Major, Top Left, Snake OFF.

Сводка показывает число кабинетов, число модулей на кабинет, размер модуля в пикселях, размер кабинета, разрешение Screen и общее число пикселей. Разрешение Screen выводится из сетки, отдельного редактора разрешения в Alpha нет. Zoom/pan, выбор кабинета и попиксельный preview не входят в этот минимальный этап.

## 3. Интеграция и состояние

- Изменения production-кода ограничены `packages/app` и необходимой конфигурацией запуска/сборки в корне. `packages/core`, его public API, reference fixtures и математические тесты сохраняются.
- Renderer импортирует только public barrel `@ledmap/core`. Позиции пути берутся из `cabinetOrder()`, логические номера — из `cabinetIndex()`. Формулы Numbering/Direction/Snake в app не повторяются.
- Канонические входы Alpha: `CabinetEngineConfig` плюс идентификаторы и имя Screen/Grid. Через `createScreen()` и `createCabinetGrid()` собирается согласованный readonly snapshot: Screen ссылается на Grid, Grid — на Screen; `mappingRegions` пуст. Размер кабинета и разрешение Screen пересчитываются из входной геометрии. Это адаптер представления, без изменения доменной модели.
- Проверка cabinet pixel layout использует публичный `decomposeCabinetPixel(layout, { x: 0, y: 0 })`, который валидирует все размеры и произведения. Внутренние helpers core не импортируются. App вычисляет размеры для сводки и отрисовки, не реализует собственный pixel mapping.
- Текст редактируемых полей отделён от последнего допустимого snapshot. Новый snapshot заменяет предыдущий атомарно после всех проверок; производные индексы и порядок пересчитываются и не сохраняются.
- Electron main отвечает за окно и lifecycle, renderer — за форму и Canvas. В renderer отключена Node integration, включена context isolation; загрузка ограничена приложением. Привилегированный IPC и preload API для этого этапа не нужны.
- Стек: TypeScript strict, Electron + electron-vite, HTML5 Canvas, без нового UI framework. `npm run build` должен собирать Electron-приложение; Windows installer остаётся Phase 8.

## 4. Ошибки и ограничение preview

Все шесть размерных полей принимают только положительные `Number.isSafeInteger` значения. Пустой ввод, дроби, ноль, отрицательные и небезопасные числа дают сообщение у поля. Отдельно проверяются безопасные произведения: число кабинетов, разрешение Screen по обеим осям и общее число пикселей; layout-произведения проверяет core. Ошибки `DomainError` отображаются без падения окна.

Для Alpha установлен максимум **1024 кабинета** и **65 536 модулей суммарно**. Лимиты проверяются до `cabinetOrder()` и до выделения массивов/отрисовки. Это ограничения preview в app, не новые ограничения core. Пиксели поштучно не выделяются и не рисуются; Canvas имеет размеры viewport с учётом devicePixelRatio, а не полное LED-разрешение. При слишком мелком масштабе подписи и линии модулей скрываются с пояснением; путь и контуры кабинетов сохраняются.

При невалидном вводе или превышении лимита остаётся последний допустимый preview с явным сообщением, что изменения ещё не применены. После исправления формы preview обновляется. Никакого молчаливого округления или обрезания значений.

## 5. Приёмка

| Проверка | Ожидаемый результат |
|---|---|
| Запуск и Create Screen | `npm run dev` открывает Electron; действие создаёт одну сетку и выводит Canvas |
| Начальная геометрия REF-001 | 12 кабинетов, кабинет 128×128 px, Screen 512×384 px, 196 608 px |
| Физические ID | `C01 C02 C03 C04 / C05 C06 C07 C08 / C09 C10 C11 C12` при любом ordering |
| Row / LTR / Snake ON | Путь `C01 C02 C03 C04 C08 C07 C06 C05 C09 C10 C11 C12`; логические подписи по физическим строкам: `1 2 3 4 / 8 7 6 5 / 9 10 11 12` |
| Row / LTR / Snake OFF | Путь `C01…C12`, физические ID и геометрия прежние |
| Остальные режимы | Обе Direction для Row и Column, Snake ON/OFF: путь и подписи совпадают с core; переключение Numbering не создаёт недопустимую пару |
| Прямоугольные модули | При исходной сетке 4×3 и layout 3×2 по 5×7 px: кабинет 15×14 px, 210 px; Screen 60×42 px, 2520 px; видимые пропорции соответствуют геометрии |
| Минимальные сетки | 1×1, 1×N, N×1 корректно отображаются при всех допустимых режимах |
| Ошибки | Пустое поле, 0, отрицательное, дробь, unsafe integer, overflow произведения и превышение лимитов не обрушивают приложение; исправление восстанавливает обновление |
| Resize и плотность пикселей | Preview вписывается без искажения пропорций и обрезания; подписи читаемы на начальной сетке |

Автоматические проверки: существующая регрессия core; целевые Vitest-тесты адаптера app на переключение оси, атомарное применение валидного состояния и отказ до построения слишком большой сетки. `npm test`, `npm run typecheck`, `npm run lint`, `npm run build` проходят. Реальное Electron-окно проверяется отдельно по таблице; результаты smoke-проверки и снимок начального preview прилагаются к отчёту. Локальные проверки не объявляются результатом GitHub Actions.

## 6. Утверждённый план реализации

1. Подключить Electron/electron-vite, main и renderer entrypoints, scripts dev/build и необходимые TypeScript/ESLint настройки; добавить инструкцию запуска.
2. Реализовать форму, адаптер readonly snapshot, валидацию и лимиты preview; подключить существующий Cabinet Engine.
3. Нарисовать Canvas: физические кабинеты, модули, отдельные логические номера, направленный путь, fit-to-window и сводку.
4. Выполнить автоматические проверки и Electron smoke-приёмку; представить diff и отчёт. Пользователь разрешил отдельные commits `docs: define early alpha ui` и `feat(app): add cabinet grid alpha visualizer`.

Одобрение этой спецификации и ADR-017 разрешает только описанный Early Alpha UI; расширение scope требует отдельного плана.
