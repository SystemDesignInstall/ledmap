Дата: 2026-10-06. План этапа одобрен пользователем командой «приступай и сделай коммит что бы гитхаб все увидел» после предложенного порядка работ. База: текущий `origin/master`, `b6a0278526347ed56d525451bb167b9270db9b0f`. Отдельные ветка/worktree: `feat/hardware-capacity-profiles` / `.worktrees/hardware-capacity-profiles`. Preflight завершён; спецификация записана до production-кода.

## Контракт этапа

1. В канонической V2-модели Processor получает необязательный снимок профиля: название, источник и его редакция, режим (частота кадров, глубина цвета, скорость линии), явные пиксельные пределы Processor и одного Port. Отсутствующий предел означает unknown. Формула пропускной способности и интерполяция режимов отсутствуют.
2. Port получает необязательное ручное переопределение: предел, причина и режим, для которого оно установлено. Оно применяется только при точном совпадении режима родительского профиля; при другом режиме сохраняется как неактивное намерение и выдаёт предупреждение. Смена режима не уничтожает пользовательские данные. Удаление профиля не уничтожает переопределение.
3. Источник manufacturer обозначает введённую оператором ссылку на документацию, а не сертифицированную совместимость. Встроенного vendor-каталога в этом этапе нет: документация NovaStar VX1000 Pro V1.2.0 указывает максимумы и список частот отдельно, что не разрешает автоматически распространять максимум на любой режим. UI явно показывает происхождение и unknown.
4. Pure core считает used/capacity/headroom по реальным Cabinet → Receiver → Port → Processor. Существующая перегрузка сохраняет assignments и даёт отдельную ошибку. Auto Allocate учитывает известные пределы порта и устройства по итоговому состоянию, сохраняет ручные цепочки/locks; неизвестный предел настроенного профиля исключает новые назначения. Без профиля сохраняется прежнее поведение с предупреждением о неизвестной транспортной ёмкости.
5. Настройка профиля/переопределения — отдельная атомарная команда Apply; невалидное поле отклоняет всю команду. Новые ручные назначения и переносы проверяют итоговые нагрузки затронутых Port/Processor, включая освобождённое место; перенумерация и физические координаты не меняются. Настройки могут фиксировать фактическую перегрузку для последующего исправления.
6. Сохраняется только intent. Новый строгий формат `.ledmap` v6 содержит необязательные поля профиля/переопределения; старые v1–v5 продолжают загружаться. Проект без нового intent сохраняется прежним v5. Запись проекта с новым intent в v3–v5 отклоняется, предотвращая тихую потерю настроек. Производные нагрузки/отчёты не сохраняются. Source/session/history/autosave используют одинаковый контракт.
7. Hardware Inspector показывает профиль, режим, источники, used/max/headroom, активность override и ошибки. Его UI вызывает готовый core. Изменения поддерживают один Undo/Redo и Save/Open. Полный продуктовый P1 и последующие экспорт отчёта/крупномасштабное профилирование остаются отдельными последовательными задачами.

## Приёмка

REF-001–004; старые v1–v5 документы; v6 round-trip и детерминированные байты; отсутствие derived data; неправильные числа/enum/unknown fields/getters/лишние ключи и некорректные режимы; независимые Port/Processor overload; unknown; неактивный override; whole-Cabinet partial allocation и locks; атомарное assignment/reassignment; Undo/Redo и Save/Open; реальный Electron UI smoke и визуальные снимки. Полные tests/typecheck/lint/build/license/audit/smoke, затем коммит/push/PR и exact-head CI.

## Источники и rollback

Реализация собственная, на канонических LedMAP model/planner/validator/serializer. Внешний код, assets и vendor dataset не копируются; B.L.I.N.K source copied = NO. Первичный источник для определения границ утверждений: [NovaStar VX1000 Pro Specifications V1.2.0, PDF pp. 11–12](https://oss.novastar.tech/uploads/2025/10/VX1000-Pro-All-in-One-Controller-Specifications-V1.2.0.pdf). Каталог профилей требует отдельного evidence review для каждого режима.

Rollback: revert этапа и rebuild. Старое приложение отклоняет v6 как unsupported вместо потери intent. Перед открытием настроенного проекта старой версией нужно сохранить отдельную копию с явно удалёнными профилями/override; исходный v6 сохраняется. Зависимости не меняются.
