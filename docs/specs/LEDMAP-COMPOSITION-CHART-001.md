Status: implemented, pending review. The user approved starting this stage on 2026-10-04 after review of pixl Grid and the current LedMAP workspaces. The user approved Composition canvas drawing parity, Clean View and removal of the inspector thumbnail on 2026-10-05. Unit tests, typecheck, lint, build and Electron smoke passed on 2026-10-05.

## Purpose and ownership

Composition owns Screen placement in project pixel coordinates and each Screen's saved drawing. Input Canvas and Mapping Region remain separate: changing a Screen's Composition position does not silently move a Mapping Region. The existing **Map from Composition Position** action is the explicit bridge.

The canonical workspace label remains **Composition**. Test previews the chart and sends the same frame to Live Output. Export writes actual-pixel PNG files. No hardware address, Cabinet ordering, or PixelMap is persisted as chart data.

## Frame

New projects use `fit`: the minimal bounding rectangle of the Screens. Its origin may be negative, and gaps between Screens remain inside the frame. Existing files may also contain `fixed`, an explicit signed origin and positive width and height. LedMAP continues to honor saved fixed frames so existing PNG and Live Output geometry does not change on Open. The Composition UI no longer exposes shared frame or gap-background controls.

The persisted frame model has two modes:

- `fit`: the minimal bounding rectangle of the Screens. Its origin may be negative; gaps between Screens remain inside the frame.
- `fixed`: an explicit signed integer origin and positive integer width and height in pixels. Every Screen must fit inside the rectangle for whole-composition PNG export. A moved Screen outside the frame produces a blocking diagnostic instead of a clipped deliverable.

The frame is a Composition delivery boundary. It does not change Screen resolution or Input Canvas resolution. The PNG renderer accepts dimensions at most 32767 pixels per axis and at most 64 Mi pixels in total.

## Saved chart settings

The app owns a versioned `ledmap.compositionChart` entry in the existing `.ledmap` v4 `extensions` object. The left panel contains only the Screen list. Selecting a Screen opens **Screen drawing** in the right inspector, with that Screen's palette, labels, cabinet lines, fill color or transparency, text shadow, caption and PNG logo. The central Composition canvas shows the drawing of every visible Screen immediately; the inspector has no separate thumbnail. The logo is limited to 256 KiB and 512×512 pixels and must fit its Screen. Screen drawings are keyed by stable Screen IDs; changing one Screen cannot change another. Earlier shared frame and appearance fields remain readable for existing files. No project schema version or core runtime dependency changes are required because these settings affect app rendering only. Other extension entries are preserved.

An edit to these settings is a document mutation: it marks the project dirty, participates in Undo/Redo and recovery autosave, and survives Save/Open. A malformed chart extension blocks Open with a diagnostic rather than silently replacing settings.

## Rendering and outputs

The output frame is generated by the app's deterministic drawing engine and consumed by Composition, Test, Live Output and PNG export. Composition places editor selection, resize handles and optional overlays above the drawing without opaque Cabinet fills. Clean View hides editor chrome; transparent pixels are represented by a checkerboard in Composition. New projects use a transparent output background; saved opaque backgrounds remain readable. Each Screen may use solid color, white grid, Cabinet checkerboard, horizontal gray gradient or RGB bars, with optional Screen labels, Cabinet IDs, Cabinet coordinates, A1-style column/row labels and cabinet borders. Text shadow is selectable per Screen. A PNG logo is placed at its native dimensions in the upper-right corner of its Screen; the caption is placed at the upper-left corner.

`screen-drawings.png` uses the selected output canvas background. `screen-mask.png` contains opaque white Screen regions and transparent pixels elsewhere, including gaps. Both use the same origin and resolution. Per-Screen PNG export uses that Screen's own bounds. The Test and Live Output previews are the same generated TestFrame; Live Output composites transparency against black on the display.

## Acceptance

1. Two Screens with a gap and a negative frame origin yield the specified PNG dimensions; the mask has zero alpha in the gap and full alpha inside each Screen.
2. An out-of-frame Screen blocks whole-composition PNG export. An invalid settings edit leaves the previous document intact.
3. Independent Screen drawings, colors and logos survive Save/Open, Undo/Redo, and recovery serialization. Unrelated extension data remains unchanged.
4. Composition has no Preview Chart, Export Chart or Output canvas section. New projects fit PNG bounds to Screens automatically. Test offers **Screen drawings** and Export offers the matching PNG pattern. Live Output receives the same frame and settings.
5. Core reference behavior remains unchanged. Unit tests, typecheck, lint, build and Electron smoke pass.
6. Changing one Screen's color updates only its drawing on the Composition canvas. Clean View toggles editor chrome without changing the document, and the right inspector has no drawing thumbnail.

## Separate contracts

Half-height/half-width cabinets, absent physical cabinets, expression syntax in numeric fields, `.pg3` import, After Effects JSX, SVG and Resolume XML require separate contracts and acceptance fixtures. Visual transparency or masking does not represent a physically absent cabinet.
